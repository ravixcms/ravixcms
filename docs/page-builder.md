# صفحه‌ساز تصویری Ravix (مرحله چهارم)

صفحه‌ساز بدنهٔ یک **صفحهٔ ثابت** را به‌صورت بصری طراحی می‌کند. مسیر: **پنل ← ظاهر سایت ← صفحه‌ساز** (`/panel/builder/`).

## ۱. مراحل استفاده

1. در **صفحات** یک صفحهٔ ثابت بسازید (مثلاً «درباره ما») و آن را «منتشرشده» کنید. (صفحه‌ساز صفحهٔ جدید نمی‌سازد؛ نشانی و سئو از همان صفحه است.)
2. **صفحه‌ساز ← طراحی** را بزنید. ویرایشگر سه بخش دارد: راست **پنل المان‌ها**، وسط **بوم**، چپ **تنظیمات مورد انتخاب‌شده**.
3. یک **بخش** به بوم بکشید (یا کلیک کنید). هر بخش با یک ردیف و یک ستون شروع می‌شود. برای ستون‌بندی، **ردیف ۲/۳/۴ ستونه** (یا ۱/۳+۲/۳) بکشید یا در تنظیمات ردیف «افزودن ستون» / «تقسیم مساوی» بزنید.
4. **عنوان، متن، تصویر، دکمه** را داخل ستون‌ها بکشید. روی هر مورد کلیک کنید تا تنظیماتش باز شود:
   متن/نشانی، رنگ، اندازهٔ متن، تراز، پس‌زمینه (رنگ یا تصویر برای بخش)، حاشیه (ضخامت/نوع/رنگ/گردی)، فاصلهٔ داخلی و فاصله تا عنصر بعد، عرض ستون (از ۱۲)، رفتار ستون‌ها در تبلت/موبایل.
   مسیر بالای پنل تنظیمات (بخش › ردیف › ستون › عنصر) برای انتخاب والدها است.
5. بالای صفحه: **دسکتاپ/تبلت/موبایل** عرض بوم را شبیه‌سازی می‌کند؛ **پیش‌نمایش سایت** صفحه را با قالب واقعی سایت (هدر، فوتر، CSS نهایی) در همان عرض نشان می‌دهد.
6. **ذخیره:** هر تغییر پس از ~۱٫۵ ثانیه خودکار در *پیش‌نویس* ذخیره می‌شود (وضعیت کنار نام صفحه)؛ دکمهٔ «ذخیره» یا `Ctrl+S` فوری ذخیره می‌کند. `Ctrl+Z` / `Ctrl+Y` واگرد و ازنو، `Delete` حذف مورد انتخاب‌شده.
7. **نسخه‌ها:** «ذخیرهٔ نسخهٔ جدید» یک تصویر ثابت می‌سازد؛ «بازیابی» هر نسخه را در پیش‌نویس می‌گذارد (قبلش از وضعیت فعلی خودکار نسخه‌ای ساخته می‌شود تا چیزی از دست نرود). بازیابی سایت را تغییر نمی‌دهد.
8. **انتشار:**
   - *نویسنده*: «ارسال برای تأیید» ← یک نسخهٔ «در انتظار تأیید» ساخته می‌شود؛ سایت تغییری نمی‌کند.
   - *مدیر*: «انتشار» پیش‌نویس را مستقیم منتشر می‌کند، یا در **نسخه‌ها** نسخهٔ در انتظار را **تأیید و انتشار** / **رد** می‌کند. «لغو انتشار طرح» صفحه را به محتوای Markdown برمی‌گرداند.
9. **ویرایش مجدد:** هر زمان دوباره وارد همان صفحه شوید؛ پیش‌نویس همان‌جا است. تغییر پیش‌نویس بعد از انتشار تا انتشار بعدی روی سایت اثر ندارد.

وضعیت خود صفحه (منتشرشده/پیش‌نویس) همچنان از بخش «صفحات» کنترل می‌شود؛ صفحهٔ پیش‌نویس حتی با طرح منتشرشده برای عموم ۴۰۴ است.

## ۲. تست Drag & Drop

### الف) دستی (۲ دقیقه)
1. ویرایشگر یک صفحهٔ خالی را باز کنید. «بخش» را از راست بکشید و روی متن «صفحه خالی است» رها کنید ← یک بخش ساخته می‌شود.
2. «عنوان» را بکشید و روی کادر نقطه‌چین ستون رها کنید. «دکمه» را بکشید و روی **نیمهٔ بالایی** عنوان رها کنید ← دکمه *قبل* از عنوان می‌نشیند (خط آبی محل درج را نشان می‌دهد؛ نیمهٔ پایینی ← بعد از آن).
3. «ردیف ۲ ستونه» را بکشید و روی **لبهٔ پایینی بخش** رها کنید ← ردیف در انتهای بخش اضافه می‌شود (رها کردن روی یک ردیف، قبل/بعد از همان ردیف درج می‌کند).
4. موس را روی عنصری ببرید تا نوار ابزار آبی بالای آن بیاید؛ **دستگیره (⋮⋮)** را بکشید و داخل ستون دیگر رها کنید ← عنصر جابه‌جا می‌شود (کادر خط‌چین آبی = رها کردن در انتهای ستون).
5. دو بخش بسازید؛ دستگیرهٔ نوار ابزار یک بخش را بکشید و روی بخش دیگر رها کنید ← ترتیب بخش‌ها عوض می‌شود.
6. چند ثانیه صبر کنید تا «ذخیره شد» بیاید، صفحه را Refresh کنید ← همان چیدمان برمی‌گردد. `Ctrl+Z` آخرین جابه‌جایی را برمی‌گرداند.
7. جایگزین بدون ماوس (دسترس‌پذیری): روی یک مورد در پنل راست کلیک کنید؛ در محل انتخاب‌شده (یا انتهای صفحه) درج می‌شود. دکمه‌های ↑ ↓ نوار ابزار هم ترتیب را عوض می‌کنند.

### ب) خودکار با مرورگر واقعی
```bash
pip install playwright && playwright install chromium     # یک‌بار
python scripts/e2e_builder.py                            # HEADED=1 SLOWMO=300 برای تماشا
```
اسکریپت دیتابیس موقت، داده‌ی اولیه و سرور را خودش می‌سازد و پاک می‌کند و ~۵۰ بررسی را با رویدادهای واقعی موس انجام می‌دهد:
کشیدن از پنل به بوم، ترتیب درج، جابه‌جایی بین ستون‌ها و ردیف‌ها، تغییر ترتیب سکشن‌ها، تنظیمات و استایل، ستون‌بندی و حالت‌های دستگاه،
ذخیرهٔ خودکار و بازگشت پس از Refresh، واگرد/ازنو، انتخاب تصویر، پیش‌نمایش واقعی، نسخه/بازیابی، انتشار، جریان تأیید نویسنده↔مدیر و تزریق XSS.

> نکتهٔ فنی: Drag & Drop با HTML5 DnD بومی پیاده شده است. در اتوماسیون، حرکت ناگهانی موس می‌تواند هاور را عوض کند و دستگیره پیش از شروع درگ ناپدید شود؛
> ویرایشگر تا هنگام فشردن دستگیره هاور را قفل می‌کند (در آزمون سرتاسری پوشش داده شده است).

## ۳. معماری

```
apps/builder/
  schema.py     جدول SPECS (تنها منبع حقیقت)، اعتبارسنجی، مهاجرت نسخهٔ سند
  render.py     رندر امن سند ← HTML + <style> (فقط عناصر مجاز، escape، بدون اسکریپت)
  models.py     PageDesign (پیش‌نویس + revision + اشاره‌گر نسخهٔ منتشرشده)، DesignVersion (snapshot ثابت)
  services.py   ذخیره، نسخه، ارسال/تأیید/رد/انتشار/لغو، بازیابی (تراکنشی، قفل ردیف)
  views.py      ویرایشگر، پیش‌نمایش، APIهای JSON (CSRF + مجوز)
  public.py     اتصال به سایت عمومی (published_body)
static/builder/ builder.js (ویرایشگر بدون وابستگی)، builder.css
```

**سند** (نسخهٔ ۱): `{"schema_version":1, "meta":{...}, "sections":[{"id","props","rows":[{"id","props","columns":[{"id","props","elements":[{"id","type","props"}]}]}]}]}`؛
نوع عنصر ∈ `heading | text | image | button`. تصاویر فقط با **شناسهٔ رسانه** ارجاع می‌شوند. سقف‌ها: ۴۰ بخش، ۲۰ ردیف/بخش، ۶ ستون/ردیف (مجموع عرض ≤ ۱۲)، ۳۰ عنصر/ستون، ۱۲۰۰ گره، ۴۰۰ کیلوبایت JSON.

**یک منبع حقیقت:** `SPECS` نوع، بازه، گزینه‌ها و ویژگی CSS هر فیلد را تعریف می‌کند و سه جا از آن استفاده می‌شود: اعتبارسنجی سرور، ساخت فرم پنل تنظیمات در مرورگر (`client_specs`) و تولید CSS (هم `render.py` و هم `applyStyle` در جاوااسکریپت).
بنابراین بوم و سایت یک قاعده دارند و ویژگی تعریف‌نشده نه پذیرفته می‌شود نه رندر.

**امنیت و جلوگیری از JavaScript دلخواه**
- ورودی: کلید ناشناخته، نوع ناشناخته، رنگ غیرهگز، عدد خارج از بازه، نشانی غیرمجاز (`javascript:`، `data:`، `//host`، `\`، فاصله/کنترل، نقل‌قول) ← ۴۲۲ و چیزی ذخیره نمی‌شود.
- خروجی: متن‌ها `escape` می‌شوند؛ هیچ `on*`، `<script>`، `style=` درون‌خطی یا HTML آزاد ساخته نمی‌شود؛ سبک‌ها فقط از مقدارهای اعتبارسنجی‌شده در یک بلوک `<style>` می‌آیند. رندر در هر درخواست از روی سند انجام می‌شود و سند پیش‌تر دوباره اعتبارسنجی می‌شود (سند دستکاری‌شدهٔ دیتابیس ← بازگشت به Markdown، نه ۵۰۰).
- CSP سایت عمومی (`script-src 'self'`) همچنان برقرار است؛ پیش‌نمایش در iframe با `sandbox="allow-same-origin"` (بدون اسکریپت) بارگذاری می‌شود.
- CSRF (توکن در هدر `X-CSRFToken`)، پاسخ JSON برای ۴۰۱/۴۰۳، قفل خوش‌بینانهٔ `revision` (ذخیرهٔ دو ویرایشگر هم‌زمان ← ۴۰۹)، مجوزها در لایهٔ سرویس هم بررسی می‌شوند، همهٔ رویدادها در گزارش audit ثبت می‌شوند.

**نسخه‌بندی و بازیابی:** `DesignVersion` ثابت است (فقط وضعیت بازبینی‌اش تغییر می‌کند). `schema_version` + `migrate_document()` جای ارتقای نسخه‌های قدیمی سند را مشخص می‌کند؛ بازیابی هر نسخه از همین مسیر اعتبارسنجی/ارتقا می‌گذرد.

**سازگاری با سیستم صفحات و قالب**
- `PageDetailView` اگر طرح منتشرشده باشد `body_html` را از صفحه‌ساز می‌گیرد؛ نشانی، سئو (توضیحات از متن طرح)، breadcrumbs، sitemap و وضعیت انتشار همان‌ها هستند.
- قالب فقط دو فیلد اختیاری `page.builder` و `page.show_title` را می‌بیند ([`docs/themes.md`](themes.md)). بدنه به رنگ اصلی قالب (`--rv-primary`) وابسته است، پس با تغییر ظاهر سایت هماهنگ می‌ماند.

## ۴. محدودیت‌های شناخته‌شده (عمدی در این مرحله)
- فقط صفحه‌های ثابت؛ نوشته‌ها و صفحهٔ اصلی با صفحه‌ساز طراحی نمی‌شوند.
- سبک‌ها برای هر دستگاه جدا تنظیم نمی‌شوند؛ فقط رفتار زیر هم رفتن ستون‌ها (تبلت/موبایل) قابل تنظیم است.
- ویرایش هم‌زمان دو نفر قفل نرم دارد (۴۰۹ و بارگذاری مجدد)، ادغام خودکار ندارد.
