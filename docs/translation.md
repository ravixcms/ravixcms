# راهنمای ترجمه و چندزبانگی (برای سازندگان قالب و افزونه)

Ravix رابط کاربری را به **۱۰ زبان** ارائه می‌دهد: `fa`، `en`، `ar`، `tr`، `es`، `fr`، `de`، `ru`، `pt-br`، `zh-hans`.
فقط **رابط** ترجمه می‌شود (پنل، قالب پیش‌فرض، ایمیل‌ها، پیام‌های خطا)؛ **محتوای کاربر** (نوشته‌ها، صفحه‌ها، دسته‌ها) ترجمه نمی‌شود
و همان‌طور که نوشته شده در همهٔ زبان‌ها نمایش داده می‌شود. این راهنما می‌گوید قالب یا افزونهٔ شما چطور در این سامانه شرکت کند.

## ۱. چهارچوب کلی

| موضوع | رفتار |
|---|---|
| انتخاب زبان | ۱) پیشوند آدرس (`/de/blog/`) ← ۲) کوکی `ravix_lang` ← ۳) زبان نمایهٔ کاربر ← ۴) «زبان پیش‌فرض» در تنظیمات سایت ← ۵) فارسی |
| آدرس‌های سایت عمومی | همیشه با پیشوند زبان: `/fa/…`، `/en/…`. آدرس بدون پیشوند (`/blog/x/`) به آدرس پیشوندی هدایت می‌شود (۳۰۲ برای زبان انتخابی بازدیدکننده، ۳۰۱ برای پیش‌فرض سایت) |
| جهت متن | خودکار: `rtl` برای `fa` و `ar`، و `ltr` برای بقیه |
| تاریخ و عدد | تقویم جلالی و رقم فارسی **فقط** برای `fa`؛ بقیه میلادی و رقم لاتین |
| فونت | فارسی/عربی: Vazirmatn؛ لاتین/سیریلیک: Inter؛ چینی: Inter + فونت سیستم |
| سئو | `<link rel="alternate" hreflang>` برای همهٔ زبان‌ها (و `x-default`) و `/sitemap.xml` به‌صورت فهرست sitemap هر زبان؛ هر دو را هسته می‌سازد |

## ۲. قواعد نوشتن متن قابل‌ترجمه (برای قالب و افزونه یکسان)

1. **متن مبنا (msgid) انگلیسی است.** فارسی هم یک ترجمه است (`fa`) و باید مثل بقیه به‌صورت فایل ترجمه بیاید، نه داخل کد.
2. جمله را **تکه‌تکه نچسبانید**؛ ترتیب کلمه‌ها در زبان‌ها فرق می‌کند. به‌جای `"Posted by " + name` از جانگهدار نام‌دار استفاده کنید:
   `gettext("Posted by %(author)s") % {"author": name}`، و در قالب `{% blocktrans with author=post.author %}Posted by {{ author }}{% endblocktrans %}`.
3. جانگهدارها **نام‌دار** باشند (`%(name)s`)، نه `%s`. نشانهٔ درصدِ لفظی را `%%` بنویسید.
4. متن را بدون HTML و بدون فاصله‌های اضافه کلید بزنید؛ اگر لازم است یک پیوند وسط جمله باشد، جمله را به دو متن جدا یا با `blocktrans` بشکنید.
5. نام برند، قالب‌ها و کدها (`RSS`، `Atom`) را ترجمه نکنید.
6. **متن‌هایی را که هسته دارد دوباره تعریف نکنید.** ترجمهٔ هسته همیشه بر ترجمهٔ قالب/افزونه می‌چربد (بخش ۶)؛ برای متن جدید خودتان، جملهٔ انگلیسی یکتا بنویسید.

## ۳. ساخت قالب چندزبانه

### ۳.۱ قالب‌ها

```django
{% load ravix_theme i18n %}
{% get_current_language as LANGUAGE_CODE %}{% get_current_language_bidi as LANGUAGE_BIDI %}
<html lang="{{ LANGUAGE_CODE }}" dir="{% if LANGUAGE_BIDI %}rtl{% else %}ltr{% endif %}">
…
<a href="{{ site.home_url }}">{% trans "Home" %}</a>
<p>{% blocktrans with author=post.author_name %}Posted by {{ author }}{% endblocktrans %}</p>
{% language_switcher %}   {# گزینشگر زبان؛ معمولاً در پاورقی #}
```

- فقط کتابخانه‌های `ravix_theme` و `i18n` در قالب مجازند.
- `<html lang dir>` را حتماً مثل بالا بگذارید تا جهت و فونت درست شوند. `{% theme_head %}` خودش `hreflang`، `canonical` و `og:locale` را می‌گذارد.
- **آدرس‌ها را سخت‌کد نکنید.** از `site.home_url`، `site.search_url`، `post.url`، `category.url` … استفاده کنید؛ این‌ها پیشوند زبان را دارند.
- تاریخ/عدد/پول: `{{ post.date|local_date }}`، `{{ post.date|local_datetime }}`، `{{ n|local_digits }}`، `{{ price|money }}` (همه به زبان فعال حساس‌اند؛ `fa_digits` برای سازگاری با قالب‌های قدیمی مانده است).

### ۳.۲ CSS دوجهته

از ویژگی‌های **منطقی** استفاده کنید تا همان CSS در هر دو جهت کار کند:

| به‌جای | بنویسید |
|---|---|
| `margin-left` / `padding-right` | `margin-inline-start` / `padding-inline-end` |
| `left: 0` / `right: 0` | `inset-inline-start: 0` / `inset-inline-end: 0` |
| `text-align: left` / `right` | `text-align: start` / `end` |
| `border-left`، `border-top-left-radius` | `border-inline-start`، `border-start-start-radius` |
| `float: right` | `float: inline-end` |

آیکن‌های جهت‌دار (مثل پیکان «بعدی») را برای `rtl` با `[dir="rtl"] .icon { transform: scaleX(-1); }` برگردانید. فونت را خودتان ثابت نکنید؛ پشتهٔ فونت انتخابی مدیر
(`--rv-font`) را به‌ازای زبان هسته تنظیم می‌کند.

### ۳.۳ فایل ترجمهٔ قالب: `locale/<زبان>.json`

برای قالب **نیازی به gettext و کامپایل نیست**؛ یک فایل JSON ساده برای هر زبان بگذارید. Ravix خودش آن را کامپایل می‌کند
(پس در بستهٔ قالب هیچ فایل دودویی نمی‌آید).

```
my-theme/
├── theme.json
├── templates/…
└── locale/
    ├── fa.json
    ├── de.json
    └── pt-br.json
```

```json
{
  "Read the full story": "Ganze Geschichte lesen",
  "Posted by %(author)s": "Veröffentlicht von %(author)s"
}
```

- کلید = دقیقاً همان متن انگلیسی که در `{% trans %}`/`{% blocktrans %}` نوشته‌اید؛ مقدار = ترجمه. جانگهدارها باید در ترجمه هم **عیناً** بیایند.
- نام فایل: کد زبان پشتیبانی‌شده + `.json` (`fa en ar tr es fr de ru pt-br zh-hans`؛ `pt_BR.json` هم پذیرفته می‌شود).
- محدودیت‌ها: حداکثر ۱۲۸ کیلوبایت و ۳۰۰۰ مدخل برای هر فایل؛ کلید تا ۲۰۰۰ و مقدار تا ۴۰۰۰ نویسه؛ فقط متن (نه عدد/آرایه)؛ مقدار خالی ممنوع.
- متن‌های جمع (`ngettext`/`{% blocktrans count %}`) در قالب پشتیبانی نمی‌شوند؛ جمله را بدون شمارش بنویسید.
- فایل نامعتبر یا نام ناجور در پوشهٔ `locale/` باعث **رد شدن بستهٔ قالب** در بارگذاری ZIP می‌شود و پیام خطا نام فایل را می‌گوید.
- نام و توضیح قالب در `theme.json` ترجمه نمی‌شوند و همان‌طور که نوشته‌اید نمایش داده می‌شوند.

## ۴. ساخت افزونهٔ چندزبانه

افزونه از **gettext استاندارد جنگو** استفاده می‌کند.

```python
# plugins/my_hello/views.py
from django.utils.translation import gettext, gettext_lazy as _

TITLE = _("Hello from my plugin")                       # در سطح ماژول: lazy
def page(request):
    message = gettext("Welcome back, %(name)s") % {"name": request.user.display_name}
```

```django
{# plugins/my_hello/templates/page.html #}
{% load i18n %}<h1>{% trans "Hello from my plugin" %}</h1>
```

### ۴.۱ استخراج و کامپایل

```bash
cd plugins/my_hello
mkdir -p locale
django-admin makemessages -l fa -l de -l fr …        # → locale/<lang>/LC_MESSAGES/django.po
# ترجمه کنید، سپس:
django-admin compilemessages                          # → django.mo
```

ساختار نهایی داخل بسته:

```
my_hello/
├── plugin.json
├── __init__.py
└── locale/
    ├── fa/LC_MESSAGES/django.po  و  django.mo
    └── de/LC_MESSAGES/django.po  و  django.mo
```

نام پوشه‌ها با قالب locale جنگو است: `fa`، `de`، `pt_BR`، `zh_Hans` (با زیرخط و حروف بزرگ). فایل `.mo` باید در بسته باشد (کامپایل در سرور انجام نمی‌شود)؛
چون در اثرانگشت افزونه می‌آید، تغییرش بعد از تأیید مدیر افزونه را غیرفعال می‌کند، مثل هر فایل دیگر.

### ۴.۲ جاوااسکریپت

متن‌های JS را با `gettext()` و `interpolate()` بنویسید، در پوشهٔ `locale/<lang>/LC_MESSAGES/djangojs.po` ترجمه کنید و در صفحه `/jsi18n/` را پیش از اسکریپت خودتان بارگذاری کنید:
`<script src="{% url 'javascript-catalog' %}"></script>`.

### ۴.۳ نکته‌ها

- کاتالوگ افزونه وقتی ثبت می‌شود که افزونه **فعال و بارگذاری** شود و با غیرفعال‌شدن/حذف از حافظه برداشته می‌شود.
- اگر دو افزونه یک msgid یکسان با ترجمهٔ متفاوت بدهند، یکی برنده می‌شود؛ متن‌های خود را یکتا بنویسید (مثلاً با پیشوند نام افزونه در جمله).
- `name` و `description` در `plugin.json` (و `theme.json`) اختیاراً چندزبانه‌اند، مثلاً `"name": {"fa": "فرم تماس", "en": "Contact form", "de": "Kontaktformular"}`؛ متن ساده هم مثل قبل مجاز است. کلیدها کد زبان‌های پشتیبانی‌شده‌اند (`fa`، `en`، `ar`، `tr`، `es`، `fr`، `de`، `ru`، `pt-br`، `zh-hans`؛ `pt_BR` هم پذیرفته می‌شود) و کد ناشناخته خطای اعتبارسنجی است. متن پیش‌فرض (برای زبانی که ورودی ندارد، و برای ابزارهایی که فقط رشته می‌خوانند) `en` است و اگر نبود اولین ورودی. حدها مثل رشته‌ٔ ساده است (نام قالب ۶۰، نام افزونه ۸۰، توضیح قالب ۳۰۰، توضیح افزونه ۵۰۰ نویسه برای هر زبان). قالب پیش‌فرض و افزونه‌های همراه برای هر ۱۰ زبان نام و توضیح دارند و آزمون این را می‌سنجد.
- افزونه‌ای که خودش HTML عمومی می‌سازد، لینک‌ها را با `reverse()` بسازد (پیشوند زبان خودکار است) و هرگز `"/blog/"` ننویسد.

## ۵. فایل‌های ترجمهٔ هسته (برای مشارکت‌کنندگان)

```
locale/<lang>/LC_MESSAGES/django.po  django.mo  djangojs.po  djangojs.mo
```

- متن جدید در کد هسته با `gettext`/`gettext_lazy` (انگلیسی) نوشته می‌شود؛ ترجمهٔ **همهٔ ۹ زبان غیرانگلیسی** باید هم‌زمان اضافه شود (انگلیسی نیاز به فایل ندارد).
- `python manage.py makemessages -a` و `-d djangojs -a` را بزنید، `.po`ها را کامل کنید و `compilemessages` را اجرا کنید. `.mo`ها در گیت هستند.
- آزمون `apps.core.tests.test_i18n_completeness` اگر متنی بدون علامت‌گذاری gettext باشد، ترجمه‌ای جا افتاده باشد، جانگهدار ناهماهنگ باشد یا `.mo` کهنه باشد، شکست می‌خورد.

## ۶. اولویت ترجمه‌ها

۱. ترجمه‌های هسته (`locale/` پروژه) — **همیشه بالاترین اولویت**؛ قالب و افزونه نمی‌توانند متن هسته را عوض کنند.
۲. افزونه‌ها و قالب‌ها به ترتیب نام (`plugin:<slug>` و `theme:<slug>`).

## ۷. چک‌لیست پیش از انتشار

- [ ] همهٔ متن‌های دیده‌شده در قالب‌ها/ویوها با `trans`/`gettext` علامت خورده‌اند (متن مبنا انگلیسی).
- [ ] جانگهدارها نام‌دارند و در همهٔ ترجمه‌ها حفظ شده‌اند.
- [ ] CSS فقط ویژگی‌های منطقی (`inline-start/end`) دارد؛ صفحه را با `/ar/` و `/en/` ببینید.
- [ ] آدرس‌ها از متغیرهای قالب/`reverse()` می‌آیند، نه رشتهٔ ثابت.
- [ ] فایل‌های `locale/<lang>.json` (قالب) یا `.mo` (افزونه) برای هر زبانی که ادعا می‌کنید هست؛ زبان‌های جاافتاده به متن انگلیسی برمی‌گردند.
- [ ] تاریخ‌ها با `local_date`/`local_datetime` نمایش داده می‌شوند، نه با رقم فارسیِ سخت‌کد.

## ۸. متن‌های اپراتور: دستورهای manage.py، خطاهای تنظیمات، preflight و لاگ

این متن‌ها برای مدیر سرور هستند، نه بازدیدکنندهٔ سایت، و **به‌صورت پیش‌فرض انگلیسی**‌اند. msgidها انگلیسی‌اند و با `cli_gettext()` (`apps/core/clilang.py`) علامت می‌خورند؛ فقط وقتی به زبان دیگری نشان داده می‌شوند که اپراتور بخواهد:

1. متغیر محیطی (یا `.env`) `RAVIX_CLI_LANG`، و اگر خالی بود،
2. `LANGUAGE_CODE` (پیش‌فرض `en`)،
3. وگرنه انگلیسی.

`fa` همراه Ravix است (`locale/fa/LC_MESSAGES/cli.po`). برای زبان دیگر فایل کامپایل‌شدهٔ `locale/<lang>/LC_MESSAGES/cli.mo` را کنارش بگذارید؛ زبان بدون کاتالوگ انگلیسی نشان می‌دهد. این انتخاب مستقل از زبان درخواست است: یک خط لاگ با زبان بازدیدکننده عوض نمی‌شود، و خطاهای راه‌اندازی پیش از آماده‌شدن Django (مثلاً `DJANGO_SECRET_KEY`) هم از همین سازوکار (با خواندن `.env`) استفاده می‌کنند. `startplugin` افزونه‌ای می‌سازد که متن‌هایش انگلیسی و با gettext علامت‌خورده است، و `startheme` از قالب پیش‌فرض (که همین‌طور است) کپی می‌گیرد. آزمون `CliCatalogTests` جلوی متن علامت‌نخورده یا ترجمهٔ جاافتاده را می‌گیرد.
