# نصب و مدیریت افزونه‌ها با نصب‌کننده

نصب‌کننده **توسعهٔ مدیر افزونه‌های مرحلهٔ ۵** است (`apps/plugins`)، نه سیستم موازی: همان `PluginRecord`، همان تأیید اثرانگشت، همان `activate/deactivate/uninstall/approve_update`. چیزی که اضافه شد: دریافت (مخزن/فایل)، اعتبارسنجی، امضا، جایگذاری اتمی، پشتیبان، ارتقا و بازگشت، قفل.

> **امضای دیجیتال اصالت بسته را تأیید می‌کند، نه بی‌خطر بودن کد را.** افزونه کد پایتون است و با دسترسی کامل سرور اجرا می‌شود. حتی بستهٔ امضاشده توسط ناشر معتبر فقط پس از بازبینی و تأیید صریح مدیر نصب می‌شود و فقط با مدیر (`plugins.manage`) قابل انجام است. نصب و فعال‌سازی خودکار وجود ندارد.

## جریان کار
```
مخزن/آپلود ─► (حافظه) ─► اعتبارسنجی بسته ─► SHA-256 + امضا + سازگاری ─► استخراج در پوشهٔ موقت ─► تطبیق اثرانگشت ─► rename اتمی
   (پنل: نصب از بسته)      مسیر/symlink/حجم/manifest      کلیدهای مورد اعتماد       .staging-*  (هم‌دیسک)            به RAVIX_PLUGIN_INSTALL_DIR
                                                                                                   │
                                  بازبینی کد و مشخصات در پنل ◄─ «در انتظار نصب» (available) ◄──────┘
                                  تأیید صریح (اثرانگشت) ─► PluginRecord (غیرفعال) ─► فعال‌سازی جداگانه
```
- هر مرحله پیش از نوشتن در پوشهٔ نصب انجام می‌شود؛ خطا در هر نقطه یعنی هیچ ردپایی روی دیسک/DB نمی‌ماند (پوشهٔ موقت پاک می‌شود، قفل آزاد می‌شود).
- هر بسته در `PluginPackage` ثبت می‌شود: منبع، SHA-256، اثرانگشت، وضعیت امضا، امضاکننده، نصب‌کننده.

## بررسی‌های بسته
مسیر مطلق/`..`/بک‌اسلش/نام تکراری، symlink و فایل غیرعادی، بستهٔ رمزگذاری‌شده، سقف تعداد فایل و حجم بازشده (ضد zip-bomb، هم در فهرست و هم هنگام خواندن)، سقف حجم zip، ساختار «یک پوشهٔ ریشه = slug»، اعتبار `plugin.json`، برابری slug/نسخه با درخواست، سازگاری (`api_version`، بازهٔ `ravix`، وابستگی‌ها)، و در نهایت **اثرانگشتِ فایل‌های استخراج‌شده = اثرانگشتِ اعتبارسنجی‌شده**. هیچ کدی اجرا یا import نمی‌شود.

## امضا و کلیدهای مورد اعتماد
- الگوریتم Ed25519 (`cryptography`). پیام امضاشده: `ravin-plugin-v1\n<slug>\n<version>\n<sha256 zip>\n<اثرانگشت محتوا>` — امضا به یک بستهٔ مشخص بسته است و بین نسخه‌ها/افزونه‌ها قابل انتقال نیست.
- **کلیدهای مورد اعتماد** (ریشهٔ اعتماد): `RAVIX_TRUSTED_PUBLIC_KEYS` (`برچسب:کلید_base64`) و کلیدهای ثبت‌شده در پنل (فقط مدیرکل، قابلیت `plugins.trust`). فقط کلید عمومی. کلید را از **کانال مستقل** بگیرید، نه از پاسخ خود مخزن.
- سیاست: بستهٔ **مخزن** همیشه باید امضای معتبر داشته باشد. **آپلود محلی** هم به‌صورت پیش‌فرض (امضای معتبر یا `RAVIX_PLUGINS_ALLOW_UNSIGNED=true`). امضای نامعتبر هرگز پذیرفته نمی‌شود.
- ساخت کلید و امضا (سمت ناشر؛ کلید خصوصی چاپ نمی‌شود، فایل 600):
  ```bash
  python manage.py plugin_keygen --out /secure/path/publisher.key       # کلید عمومی چاپ می‌شود
  python manage.py plugin_sign my_plugin.zip --key-file /secure/path/publisher.key   # signature و key_id
  ```
- مخزن: `RAVIX_REGISTRY_SIGNING_KEY_FILE` (توصیه) یا `RAVIX_REGISTRY_SIGNING_KEY`؛ نسخه هنگام *انتشار* امضا می‌شود؛ نسخه‌های قدیمی: `manage.py registry_sign`. **هیچ کلیدی در کد/مخزن نیست.**

## ارتقا، پشتیبان و بازگشت
- **ارتقا** (پنل: جزئیات افزونه ← ارتقا، یا آپلود با «ارتقا»): قفل ← نسخهٔ جدیدتر باشد ← کد فعلی باید با نسخهٔ تأییدشده یکی باشد ← **پشتیبان zip** (SHA-256 ثبت‌شده، به‌همراه manifest/تنظیمات/آخرین مهاجرت/وضعیت فعال بودن) ← استخراج و اعتبارسنجی نسخهٔ جدید ← غیرفعال‌سازی ← جایگزینی اتمی (در خطا نسخهٔ قبلی و وضعیت فعال برمی‌گردد و پشتیبان دور ریخته می‌شود).
  بعد از ارتقا، افزونه در وضعیت «تغییر کد؛ نیازمند تأیید» است: مدیر کد جدید را می‌بیند و تأیید می‌کند (مهاجرت‌ها اینجا اجرا می‌شوند)، سپس فعال می‌کند.
- **بازگشت** (پنل: پشتیبان‌ها): صحت آرشیو با SHA-256 و اثرانگشت ثبت‌شده سنجیده می‌شود؛ اگر نسخهٔ جدید مهاجرت اعمال کرده باشد، با **تأیید صریح پاک شدن داده‌های آن** مهاجرت‌ها برگردانده می‌شوند (در شکست، فایل‌ها دست‌نخورده می‌مانند)؛ سپس فایل‌ها و رکورد به نسخهٔ قبل برمی‌گردند و افزونه غیرفعال می‌ماند. هر پشتیبان یک‌بار قابل استفاده است. نگهداری: `RAVIX_PLUGIN_BACKUPS_KEEP` (پیش‌فرض ۵) در هر افزونه.
- **حذف کنترل‌شده:** غیرفعال‌سازی ← حذف (با/بدون پاک‌کردن داده) ← اختیاری «حذف فایل‌ها (با پشتیبان)»؛ فایل‌ها پاک نمی‌شوند مگر پس از آرشیو قابل‌بازیابی.
- فقط افزونه‌هایی که با نصب‌کننده در `RAVIX_PLUGIN_INSTALL_DIR` گذاشته شده‌اند ارتقا/بازگشت خودکار دارند؛ پوشه‌های دستی در `plugins/` را خودتان مدیریت کنید.

## هم‌زمانی
قفل پایگاه‌داده‌ای به‌ازای slug (`PluginOperationLock`، یکتایی روی slug): نصب، ارتقا، بازگشت و حذف فایل دو‌به‌دو هم‌زمان اجرا نمی‌شوند؛ درخواست دوم پیام «عملیات دیگری در جریان است» می‌گیرد. قفلِ مانده پس از کرش بعد از ۱۵ دقیقه آزاد می‌شود. افزونه‌های مختلف مانع هم نیستند.

## خطا و گزارش
هر شکست با پیام فارسی قابل‌فهم به مدیر نشان داده می‌شود و در «گزارش افزونه‌ها» (`PluginEvent`، نوع `install_failed`/`rollback_failed`…) ثبت می‌شود. خطای غیرمنتظره: پیام عمومی به مدیر + جزئیات فنی (traceback) فقط در گزارش.

## تنظیمات سرور
| متغیر | پیش‌فرض | شرح |
|---|---|---|
| `RAVIX_PLUGIN_WEB_INSTALL` | `false` (توسعه: `true`) | نصب/ارتقا/بازگشت از پنل. خاموش ⇒ همه خطای «خاموش است» |
| `RAVIX_PLUGIN_INSTALL_DIR` | `<پروژه>/plugins_installed` | پوشهٔ نصب خودکار (قابل‌نوشتن برای سرویس؛ در `RAVIX_PLUGIN_DIRS` اضافه می‌شود) |
| `RAVIX_PLUGIN_BACKUP_DIR` | `<پروژه>/plugin_backups` | پشتیبان‌ها (مجوز 700) |
| `RAVIX_PLUGIN_BACKUPS_KEEP` | `5` | |
| `RAVIX_OFFICIAL_REGISTRY_URL` | خالی | نشانی HTTPS مخزن؛ خالی = مخزن همین نمونه (اگر روشن است). **هیچ مخزن رسمی از پیش متصل نیست.** |
| `RAVIX_TRUSTED_PUBLIC_KEYS` | خالی | کلیدهای عمومی مورد اعتماد |
| `RAVIX_PLUGINS_ALLOW_UNSIGNED` | `false` | فقط برای آپلود محلی |

## راه‌اندازی روی سرور
```bash
sudo install -d -o ravix -g ravix -m 750 /srv/ravix/plugins_installed
sudo install -d -o ravix -g ravix -m 700 /srv/ravix/plugin_backups
# /etc/ravix/ravix.env:
#   RAVIX_PLUGIN_WEB_INSTALL=true
#   RAVIX_PLUGIN_INSTALL_DIR=/srv/ravix/plugins_installed
#   RAVIX_PLUGIN_BACKUP_DIR=/srv/ravix/plugin_backups
#   RAVIX_TRUSTED_PUBLIC_KEYS=publisher:<کلید عمومی ناشر>
#   RAVIX_OFFICIAL_REGISTRY_URL=https://plugins.ravixcms.com   # در صورت وجود
sudo systemctl restart ravix && sudo -u ravix ... python manage.py ravix_preflight
```
اگر `ProtectSystem=strict` در systemd دارید، این دو پوشه را به `ReadWritePaths=` اضافه کنید. پوشهٔ `plugins/` پروژه فقط‌خواندنی بماند.

## راهنمای مدیر سایت
1. **(مدیرکل)** کلید عمومی ناشر را در «کلیدهای مورد اعتماد» ثبت کنید (یا در env).
2. پنل ← افزونه‌ها ← **نصب از بسته**: شناسهٔ افزونه (از مخزن) یا فایل zip + امضا.
3. صفحهٔ بازبینی: مشخصات، فهرست فایل‌ها، اثرانگشت؛ کد را ببینید ← تیک اعتماد ← نصب.
4. فعال‌سازی. نسخهٔ جدید: ستون «نسخهٔ جدید» در فهرست/جزئیات ← ارتقا ← بازبینی ← تأیید ← فعال‌سازی.
5. مشکل پیش آمد: جزئیات ← پشتیبان‌ها ← بازگشت.

## محدودیت‌ها
- امضا ≠ امنیت کد؛ سندباکس وجود ندارد. ابطال کلید لوفته فقط با حذف از فهرست مورد اعتماد سایت‌هاست (CRL/زنجیرهٔ گواهی نداریم).
- مرور مخزن راه دور فقط از طریق نصب‌کننده/فهرست آخرین نسخه‌هاست؛ Plugin Directory کامل فقط مخزن همین نمونه را نشان می‌دهد.
- بازگشت مهاجرت به برگشت‌پذیری عملیات مهاجرت (فقط عملیات ساختاری مجاز) وابسته است و داده‌های ستون/جدول حذف‌شده را برنمی‌گرداند؛ پیش از ارتقای افزونه‌های دارای مدل از دیتابیس پشتیبان بگیرید.
- `rename` اتمی نیازمند هم‌دیسک بودن پوشهٔ موقت و نصب است (داخل خود `RAVIX_PLUGIN_INSTALL_DIR` ساخته می‌شود)؛ اگر پوشه روی NFS/overlay با rename غیراتمی باشد ضمانت اتمی بودن محدود است.
- تست مهاجرت و ارتقا روی SQLite اجرا شده؛ اجرای روی PostgreSQL در این محیط انجام نشد.

اجرای واقعی (بدون mock) کل جریان با کلید و بستهٔ واقعی: `python scripts/e2e_installer.py`.
