# موانع انتشار عمومی Ravix 1.0

تاریخ بررسی: ۲۰۲۶-۱۰-۲۲ · نسخهٔ درخت کاری: `0.6.1` (+ تغییرات پس از R1: ورود/کش، ایمیل، تایمرها، فید، سئو/OG/ریدایرکت، دیدگاه‌ها).
این سند **فقط گزارش** است؛ هیچ کد یا تنظیمی برای تهیهٔ آن تغییر نکرد (جز خود این فایل).

## وضعیت به‌روز (۲۰۲۶-۱۰-۲۳، نسخهٔ `0.9.0`)

**آزمون‌ها:** ۱۲۳۰ آزمون، OK روی SQLite (۵ پرش) و روی PostgreSQL 16 (۴ پرش) با پایتون ۳٫۱۳؛ `e2e_backup_restore` و `e2e_updater` روی PG16 موفق؛ `makemigrations --check` تمیز؛ `check --deploy --fail-level WARNING` بدون هشدار؛ bandit با baseline؛ pip-audit بدون آسیب‌پذیری؛ gitleaks (تاریخچه + درخت کاری) بدون یافتهٔ واقعی.

## ۱. حتماً قبل از انتشار

### ۱-۱. محدودسازی نرخ و قفل ورود برای همهٔ بازدیدکننده‌ها یک «IP» می‌بیند
- **شواهد:** `apps/accounts/throttle.py:client_ip` فقط وقتی `RAVIX_TRUST_PROXY_HEADERS=true` باشد `X-Real-IP` را می‌خواند؛ پیش‌فرض `false` است (`config/settings/base.py:310`). Gunicorn روی **سوکت یونیکس** (معماری مستند‌شده) `REMOTE_ADDR` را **خالی** می‌دهد — این را همین‌جا با یک Gunicorn واقعی روی unix socket اندازه گرفتم (`''`). نتیجه: `client_ip` همیشه `"unknown"` برمی‌گرداند.
- **اثر:** (الف) ۲۰ ورود ناموفق از هر کسی، ورود **همهٔ کاربران** را ۵ دقیقه قفل می‌کند (DoS ساده روی پنل)؛ (ب) محدودیت ۵ دیدگاه در ۱۰ دقیقه برای **کل سایت** است؛ (پ) محدودیت ایمیل (۱۰ در ساعت) سراسری است؛ (ت) لاگ ممیزی IP ندارد.
- **چرا مستند و preflight نمی‌گیرند:** `deploy/ravix-proxy.conf` هدر را می‌گذارد، ولی `docs/deployment.md` و `.env.example` پیش‌فرض را نمی‌چرخانند و `ravix_preflight` این را نمی‌سنجد.
- **پیشنهاد:** در راهنمای استقرار و نمونهٔ `ravix.env` مقدار `true` را با توضیح بگذارید؛ preflight وقتی `REMOTE_ADDR` خالی است و پرچم خاموش است خطا بدهد؛ روی VPS واقعی با دو IP متفاوت آزمایش شود. (روی VPS تأیید نشده — فقط رفتار Gunicorn و کد اندازه‌گیری شد.)

### ۱-۲. افزونه‌های همراه بسته روی نسخهٔ 1.0 نصب نمی‌شوند
- **شواهد:** `plugins/{contact_form,seo_toolkit,example_pay}/plugin.json` همه `"ravix": ">=0.5.0,<1.0.0"`؛ `apps/plugins/services.py:76` ناسازگاری را رد می‌کند. با `RAVIX_VERSION="1.0.0"` هر سه «نیازمند Ravix با نسخهٔ …» می‌شوند.
- **پیشنهاد:** بازه را `<2.0.0` کنید (یا هر سیاستی که برای API افزونه‌ها می‌خواهید)، نسخهٔ افزونه‌ها را بالا ببرید، و آزمون «افزونه‌های همراه بسته روی نسخهٔ جاری فعال می‌شوند» اضافه شود.

### ۱-۳. تاریخچهٔ git بررسی‌شدنی نیست؛ مخزن واقعی باید اسکن شود
- پوشهٔ پروژه git ندارد، پس «رازهای جاافتاده در تاریخچه» بررسی نشد (درخت کاری تمیز است ولی تاریخچه می‌تواند چیز دیگری بگوید). پیش از public کردن مخزن: `gitleaks detect` یا `trufflehog git file://…` روی **مخزن واقعی**، و اگر چیزی بود چرخاندن راز (نه فقط حذف از تاریخچه).
- هم‌چنین `db.sqlite3` و `media/` در `.gitignore` هستند؛ تأیید کنید هرگز کامیت نشده‌اند.

### ۱-۴. بستهٔ انتشار فعلی (`ravix-0.6.1.zip`) قدیمی است
- شامل هیچ‌کدام از تغییرات پس از R1 نیست (اصلاح ۵۰۰ ورود، ایمیل، تایمرها، فید، سئو/ریدایرکت، دیدگاه‌ها، مهاجرت‌های `accounts.0003/0004`، `core.0003–0005`، `content.0003–0004`، `comments.0001`). `deploy/` آن فقط تایمر `expire-orders` را دارد.
- **پیشنهاد:** نسخه‌بندی (بخش ۱-۸)، بازسازی بسته با `release.yml`، و اجرای `scripts/verify_release.py`.

### ۱-۵. هیچ‌چیز روی زیرساخت واقعی اجرا نشده
- GitHub Actions (`ci.yml`, `release.yml`) فقط از نظر نحو بررسی شده؛ **هرگز اجرا نشده** (باید ماتریس PostgreSQL سبز شود).
- مهاجرت‌های جدید روی PostgreSQL آزموده نشده؛ `scripts/vps_smoke.sh` تایمرهای جدید را نمی‌شناسد و روی هیچ VPS اجرا نشده (`docs/hosting.md`: «هنوز هیچ میزبانی آزموده نشده»).
- علت واقعی ۵۰۰ ورود روی VPS تأیید نشد (خروجی `journalctl` نرسید)؛ اصلاح سخت‌سازی انجام شد ولی «علت ریشه‌ای» اثبات‌نشده است. با ۱-۱ هم ارتباط احتمالی ندارد؛ جدا بررسی شود.
- **پیشنهاد:** یک نصب تمیز کامل روی یک Ubuntu واقعی (با دامنه/TLS آزمایشی) + اجرای `vps_smoke.sh` + پر کردن جدول `docs/hosting.md`.

### ۱-۶. دو خطای ۵۰۰ واقعی در اپ دیدگاه‌ها (کد همین نشست)
- `POST /panel/comments/bulk/` با شناسهٔ بسیار بزرگ (مثلاً ۳۰ رقم) و `GET /panel/comments/?post=<۳۰ رقم>` → `OverflowError` (SQLite) / `DataError: integer out of range` (PostgreSQL). فقط برای کاربر مدیر قابل‌رسیدن است (اثر کم)، ولی ۵۰۰ است. ریشه: `isdigit()` بدون سقف. (`apps/comments/views.py`.) اصلاح ساده: فقط شناسه‌های ≤ ۹ رقم یا گرفتن `OverflowError`.
- هم‌چنین این الگو را در هر قابلیت جدید با «شناسه از query/POST» بازبینی کنید؛ بقیهٔ مسیرهای آزموده‌شده سالم بودند.

### ۱-۷. `SECURITY.md` و `LICENSE` ناقص‌اند

### ۱-۸. شمارهٔ نسخه و آزمون‌های وابسته به آن

## ۲. بهتر است (قبل یا بلافاصله بعد از انتشار)

1. **فایل‌های اضافی در بسته:** بسته (`git archive`) آزمون‌ها، `.github`، `scripts/e2e_*`، `verify_release.py` را درست حذف می‌کند و `.env`/`db.sqlite3`/`media` اصلاً در آن نیست. ولی هنوز **شامل** این‌هاست: `docs/STATUS.md` (یادداشت‌های داخلی توسعه با ادعاهای آزمون و «کار باقی‌مانده»)، `docs/vps-smoke-runbook.md`، `plugins/example_pay` (افزونهٔ پرداخت نمونه — در محیط تولید می‌تواند گمراه‌کننده باشد)، `scripts/vps_smoke*.sh`. تصمیم بگیرید کدام‌ها برای کاربر نهایی بمانند (مثلاً STATUS به `docs/` توسعه‌دهنده یا حذف از بسته).
2. **آزمون‌ها در `media/` واقعی می‌نویسند:** `media/posts/` پروژه ~۱۰ فایل PNG آزمایشی از اجرای آزمون‌های همین نشست گرفته است (احتمالاً `test_seo_toolkit_core_compat.py` که `PluginTestCase` است نه `MediaTestCase`). در بسته نمی‌آید (media در `.gitignore`)، ولی آزمون باید در پوشهٔ موقت بنویسد. پاک‌سازی دستی `media/posts/` فعلاً انجام نشد.
3. **آزمون ناپایدار از قبل:** `apps/pluginhub/tests/test_panel.py::test_token_shown_once_and_revocable` گاهی (≈۱/۶۰) می‌شکند، چون توکن تصادفی با «x» شروع می‌شود و آزمون `"rvn_x"` را در صفحه جست‌وجو می‌کند. CI سبز را بی‌اعتبار می‌کند؛ قبل از انتشار اصلاح شود. (اجرای موازی ۴ همچنین خطاهای واقعی را پشت «cannot pickle traceback» پنهان می‌کند — در CI ترتیبی هم اجرا شود.)
4. **پیش‌فرض‌های سخت‌گیر/ریسکی:**
   - `SECURE_HSTS_PRELOAD=True` + `INCLUDE_SUBDOMAINS` به‌صورت پیش‌فرض در `production.py`: برای دامنه‌ای که هنوز HTTPS کامل ندارد غیرقابل‌برگشت‌ترین تنظیم است؛ پیش‌فرض را خاموش و در مستند توضیح دهید.
   - ثبت‌نام عمومی به‌صورت پیش‌فرض باز است (`RAVIX_REGISTRATION_OPEN=true`) و تأیید ایمیل پیش‌فرض خاموش (`RAVIX_REQUIRE_EMAIL_VERIFICATION=false`)؛ برای یک CMS عمومی، پیش‌فرض امن‌تر «بسته یا نیازمند تأیید ایمیل» است.
5. **مستندات ناقص:** هیچ مستندی برای کاربر نهایی دربارهٔ این قابلیت‌ها نیست (فقط CHANGELOG/STATUS): **دیدگاه‌ها** (مدیریت، ضداسپم، کلمات مسدود)، **ریدایرکت‌ها**، **سئو/OG/تصویر پیش‌فرض اشتراک‌گذاری**، **فید RSS/Atom**، **بازیابی رمز و تأیید ایمیل** و `send_test_email`، و **تایمرهای systemd** جدید در بخش‌هایی از README. موارد دیگر: `docs/hosting.md` قدیمی/در تناقض با وضعیت فعلی؛ `docs/api.md` فقط ۲۶ خط و فاقد هر API برای نوشته/صفحه/دیدگاه (API v1 فقط me/users/site/system/dashboard/shop دارد)؛ راهنمای «نصب برای غیرمتخصص» (R2) وجود ندارد؛ README نسخه و فهرست امکانات را به‌روز نمی‌گوید (فید، دیدگاه، ریدایرکت، ایمیل).
6. **راهنمای بازیابی و گزارش خطا:** نشانی/روش گزارش باگ (Issues، قالب issue)، `CODE_OF_CONDUCT`، و راهنمای مشارکت کامل‌تر (`CONTRIBUTING.md` ۵ خط است).
7. **`.env.example`** عباراتی از ساختار داخلی دارد («مرحلهٔ ششم»…) و برای کاربر نهایی گنگ است؛ و متغیرهای جدید (دیدگاه) آن‌جا نیامده‌اند: `RAVIX_COMMENT_LIMIT_PER_IP`، `RAVIX_COMMENT_WINDOW_SECONDS`، `RAVIX_COMMENT_MAX_DEPTH`، `RAVIX_COMMENT_MAX_LENGTH`.
8. **پاسخ‌های JSON برای مسیرهای ناشناس `/api/…`:** ۴۰۴ زیر `/api/v1/` صفحهٔ HTML (فارسی) برمی‌گرداند نه `{"detail": …}`؛ برای مصرف‌کنندهٔ API ناخوشایند است. خطاهای DRF روی مسیرهای موجود فارسی‌اند.
9. **ایمیل و SMTP:** ارسال واقعی هرگز آزموده نشده؛ `send_test_email` را روی SMTP واقعی اجرا و در مستند یک نمونهٔ کامل (Gmail/Mailgun/سرویس ایرانی) بگذارید.
10. **ریدایرکت‌ها:** برای تغییر نامک دستهٔ‌/برچسب و حذف نوشته ساخته نمی‌شود؛ ریدایرکت خودکار در لاگ ممیزی بدون «کاربر» ثبت می‌شود؛ `Page` هنوز `noindex` ندارد.
11. **حریم خصوصی دیدگاه‌ها:** IP دیدگاه‌گذار ذخیره می‌شود؛ برای انتشار عمومی (به‌ویژه برای کاربران اروپایی) سیاست نگهداری/حذف و یادداشت حریم خصوصی لازم است.
12. **دو افزونه، دو منبع حقیقت برای سئو:** `seo_toolkit` و فیلدهای هستهٔ جدید هم‌پوشانی دارند (افزونه غالب است). برای ۱.۰ یا افزونه را کنار بگذارید و `SeoMeta` را مهاجرت دهید، یا در مستند تصمیم را روشن کنید.

## ۳. بعداً (پس از ۱.۰)

- تصمیم‌های معماری معلق: استراتژی فایل‌های استاتیک قالب‌های نصب‌شده؛ **سیاست انقضای مجوز Pro** (بدون حذف داده) پیش از هر پیاده‌سازی؛ ویرایشگر تصویری (E1–E6) و نصب‌کنندهٔ یک‌دستوری (R2–R4, R6) که هنوز تأیید جدا می‌خواهند.
- ورود دومرحله‌ای (2FA) برای مدیران، ابطال نشست‌ها از پنل، فهرست دستگاه‌ها.
- تست نفوذ مستقل، مانیتورینگ و هشدار، پشتیبان آف‌سایت خودکار.
- محتوا/رسانه/قالب هنوز سایت‌محور (multisite) نیستند؛ API توکنی برای مصرف‌کنندهٔ خارجی و OpenAPI خودکار.
- کارایی: CDN، تصاویر responsive/WebP، اندازه‌گیری Core Web Vitals؛ آزمون بار.
- ویژگی‌های دیدگاه: پاسخ مدیر از پنل، ویرایش متن، اطلاع‌رسانی ایمیلی به نویسنده، افزونهٔ ضداسپم خارجی، نمایش در فید/JSON-LD.
- فید با متن کامل و تصویر شاخص؛ اعتبارسنجی W3C فید؛ پیش‌نمایش واقعی OG (فیسبوک/تلگرام/X).
- حذف کامل فایل‌های توسعه از ریشهٔ مخزن عمومی؛ ترجمه/انگلیسی‌سازی بخشی از مستندات اگر مخاطب بین‌المللی هدف است.
- سندباکس کد افزونه (در پایتون عملاً ناممکن؛ مدل اعتماد باید همچنان به‌روشنی مستند بماند).
